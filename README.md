## 分类原则：基础逻辑与市场表现分开

**01 的五种组织逻辑是唯一基础类型学**：编年型、层级型、编目型、字母表型、地理图型。每张案例必须选择一个主归属，依据是作品主导的数据/信息关系。

**02 的 18 个目录是市场表现形式标签**，用于案例检索和设计方法归纳，不是新增的基础类型。一个案例可有多个表现标签，但原图只在一个主标签目录保存一份，其他标签通过链接引用。不能仅凭“有地图”“有时间轴”“有很多图表”决定基础类型。

## 文档分工

- **01 理论定义**：每份文件按 A—E 五个维度讨论数据逻辑、统计图形/计算、视觉编码、数据/信息架构、视觉叙事；不保存案例图片，只用 Markdown 链接案例报告。
- **02 案例库**：每个标签含“00-标签说明.md”和“案例/README.md”；每张实际案例使用 `案例/CASE-xxxx-作品名/`，同目录存原图与 `分析.md`，可附基础数据 CSV 和数据字典。
- **03 统计图形分析**：独立研究统计图形所需的数据结构、聚合计算、视觉通道和适用边界；不替代 01 的基础类型学。

## 案例维护流程

1. 核验作品名称、作者、来源、日期及原图归档许可。
2. 先判断五大基础类型的唯一主归属，再选择一个主市场标签及可选辅助标签。
3. 按 [逐图分析模板](./02-信息图形类型案例/案例分析模板.md) 完成 A—E 五维分析，区分图面事实、推断和待确认信息。
4. 更新对应标签说明、[案例索引](./02-信息图形类型案例/案例索引.md)，并把可推广且有证据的规律回写 01。
5. 若新案例与旧结论冲突，记录差异与适用条件，不强行统一；不得编造数据、来源或视觉细节。
